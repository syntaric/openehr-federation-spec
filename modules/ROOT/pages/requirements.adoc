= 6. SPECIFICATION - normative requirements (N1–N43)

Requirement language is RFC 2119. Where a requirement names an IHE profile, the profile is a *proposed binding* (xref:terminology.adoc#requirement-language[§ Requirement language]): the obligation is normative, the named profile is a proposal.

== Transparency & façade

* [[n1]]*N1.* A client MUST be able to query, and to perform follow-up interactions with, the Federation Tier *with no indication that it is federated*; the interface MUST be a *conformant openEHR Query API*.
* [[n2]]*N2.* The Federation Tier MUST accept an openEHR-compliant AQL query that identifies the patient via `ehr_status/subject`, MUST treat that predicate as a *façade convenience only*, and MUST NOT execute that subject predicate at any node. _(xref:aql-facade.adoc[§7].)_

== Patient resolution (Step 1)

* [[n3]]*N3.* Before dispatch, the Tier MUST resolve `<patientId> → {node, local ehr_id}` via an identifier cross-reference service (proposed binding: IHE PIXm `$ihe-pix`). Resolution MUST occur *outside AQL*. _(xref:identity-resolution.adoc[§5.2].)_
* [[n4]]*N4.* For an undirected query, the Tier MUST obtain candidate nodes from a localization / record-locator service (proposed binding: IHE XCPD). The service's internals are out of scope. Localization answers *where the patient's data might be*; it is *not* required to answer whether that data may be released - that is consent (<<n27,N27>>), which a localizer MAY carry but MUST NOT be assumed to. _(xref:localization.adoc[§14].)_
* [[n5]]*N5.* The Tier MUST NOT require a *directly identifying identifier* of the patient (xref:identity-resolution.adoc#directly-identifying-identifier[§5.1]) to be stored in `EHR_STATUS.subject` at any node. A returned `subject` column MUST be the *re-injected resolution input*. This constrains what the *federation may require of a node*; it is not a prohibition on what a node stores (<<n34,N34>>). _(xref:identity-resolution.adoc[§5], xref:aql-facade.adoc[§7].)_
* [[n6]]*N6.* `not-resolved` outcomes *per node* MUST be recorded in metadata and MUST NOT fail the whole query. _(xref:partial-results.adoc[§11], §27.)_

== Dispatch & rewrite (Step 2)

* [[n7]]*N7.* The Tier MUST dispatch *standard, non-federated* AQL to each eligible node, scoped to that node's *resolved* `ehr_id` - keyed on `ehr_id`, *not* on `subject`. _(xref:aql-facade.adoc[§7].)_
* [[n8]]*N8.* The Tier MUST dispatch *only* to nodes where the patient is resolved (via the cross-reference service), minus any nodes removed by an optional Step-1 consent pre-filter (<<n27a,N27a>>). Dispatching to a node is *not* an assertion that consent permits release - the node decides that (<<n27,N27>>). _(xref:identity-resolution.adoc[§5.2].)_
* [[n9]]*N9.* `WHERE` clauses execute *within* each node. `LIMIT`, `OFFSET` and `ORDER BY` also execute within each node, but per-node execution alone is *not* a correct federated answer: the Tier MUST additionally apply the merge rules of <<n39,N39>>. _(Cross-node pagination is not guaranteed; xref:partial-results.adoc#aggregation-and-ordering[§11.6], xref:future.adoc[§18].)_
* [[n10]]*N10.* The Tier MUST accept an *undirected* query that identifies only the patient; the node set is derived from localization (<<n4,N4>>).
* [[n11]]*N11.* The Tier MUST accept a *directed* query that names *Endpoints*, and SHOULD accept one that names *Organizations*. The directive selects the *node set* and is *independent of patient resolution*; per-node scope is still the resolved `ehr_id`. _(xref:endpoint-directive.adoc[§8].)_

== Combine / annotate / dedup (Step 3)

* [[n12]]*N12.* The Tier MUST be able to add *Endpoint* and *Organization* attributes to rows when those attributes are selected. _(xref:result-set.adoc[§9].)_
* [[n13]]*N13.* `DISTINCT` and `ORDER BY` MUST be supported at the Federation Tier.
* [[n14]]*N14.* The Tier MUST block *undirected aggregate* queries (`SUM`, `COUNT`, `MIN`, `MAX`, `AVG`) unless cross-node correctness is guaranteed; a *directed single-node* aggregate is permitted. _(xref:aql-facade.adoc[§7].)_
* [[n15]]*N15.* By default the Tier MUST NOT deduplicate; it MUST make rows distinguishable via *endpoint provenance* (relying on `DISTINCT`). It SHOULD offer an opt-in *VERSION-identity dedup* keyed on the openEHR `object_id`, keeping the originating copy and recording suppressed endpoints. _(xref:deduplication.adoc[§10].)_
* [[n16]]*N16.* Unresponsive nodes MUST NOT contribute rows and MUST appear in `meta.endpoints[]` with a status and error; the status set includes `not-resolved`, `consent-denied` and `excluded`. _(xref:partial-results.adoc[§11].)_

== Result-set shape

* [[n17]]*N17.* The result set MUST be `{q, columns, rows}` plus `meta`; when *no* ENDPOINT attribute is selected, rows MUST NOT contain endpoint columns (single-CDR compatibility). _(xref:result-set.adoc[§9].)_
* [[n18]]*N18.* ENDPOINT attribute aliases MUST resolve name collisions with EHR-derived columns. _(xref:result-set.adoc[§9].)_
* [[n19]]*N19.* The FHIR `Endpoint` and `Organization` resources are RECOMMENDED for the registry. An `Endpoint` SHOULD carry a *defined* openEHR Query-API connection type: implementers MUST *register a real code* (e.g. `openehr-rest-query`) or bind a specified system value rather than an informal string. Every `Endpoint` MUST have a *stable unique identifier* used in directives. _(xref:endpoint-directive.adoc[§8], xref:result-set.adoc[§9], xref:addressing.adoc[§15].)_
* [[n20]]*N20.* Every `Endpoint` MUST have *exactly one* managing `Organization` (1..1), which need not be the organization that physically exposes the endpoint.
* [[n21]]*N21.* The Tier MUST maintain a *registry* mapping Organizations, Endpoints, *and* openEHR `system_id` / `creating_system_id` → CDR base URLs - the *follow-up routing table*. The registry MUST map every observed `creating_system_id`, not only node `system_id`s (a CDR may hold versions created elsewhere). _(xref:follow-up-routing.adoc[§12], xref:addressing.adoc[§15].)_

== Follow-up routing (reads & writes)

* [[n22]]*N22.* The Tier MUST support *follow-up reads* of a specific `COMPOSITION`/`VERSION` identified in a result row, routing to the *owning CDR* by (in priority order) the `creating_system_id` embedded in the `OBJECT_VERSION_ID`, else a carried `endpoint_id`, else an *ask-all* fallback. The Tier MUST NOT mutate openEHR uids. _(xref:follow-up-routing.adoc[§12].)_
* [[n23]]*N23.* The Tier MUST route a *versioned write* (`CONTRIBUTION`/commit to an existing object) to the *single controlling CDR* (`system_id == creating_system_id` of the target object) and MUST *reject* writes it cannot unambiguously route. *New-object creation* MUST target an *explicitly chosen* node (via `FROM ENDPOINT` or the `openEHR-federation-endpoint` header); creation spanning multiple nodes is disallowed in v1. _(xref:follow-up-routing.adoc[§12], xref:scope.adoc[§2.3].)_
* [[n24]]*N24.* On *every* routed follow-up (read or write) the Tier MUST convey the *authenticated client identity* to the source CDR, for audit records and access decisions. _(xref:security.adoc[§13].)_

== AuthN / AuthZ & security handoff

* [[n25]]*N25.* The client MUST authenticate to the Federation Tier; the Tier authenticates *onward* and MUST *propagate the client identity* to nodes (default mechanism: OAuth 2.0 client-credentials with a signed JWT client assertion per RFC 7523, keys published as a JWKS per RFC 7517; a regional federated-identity stack MAY be used instead - xref:annex-b-dutch-gf.adoc[Annex B]). _(Intermediaries White Paper Conformance Point #2; xref:security.adoc[§13].)_
* [[n26]]*N26.* Access decisions that need information *not visible* to the gateway MUST be *delegated to the source CDR*; the gateway MUST NOT be the sole authority for releasing sensitive data. _(xref:security.adoc[§13].)_
* [[n27]]*N27.* *Consent enforcement is the node's obligation.* Each node MUST check consent (or opt-out) before releasing data, and MUST do so *whether or not* anything upstream pre-filtered on consent. A gateway MUST NOT assume that a node appearing in a localization result is consent-cleared. _(xref:security.adoc[§13.2].)_
* [[n27a]]*N27a.* *Consent pre-filtering at Step 1 is OPTIONAL.* Where a deployment provides a *consent service* - whether standalone or bundled into localization (<<n4,N4>>) - the Tier MAY use its decision to exclude nodes before dispatch, and MUST then report each excluded node as `consent-denied` (<<n16,N16>>, this feeds <<n6,N6>>). A deployment with no such service is *fully conformant*: Step 1 simply carries no consent signal and <<n27,N27>> is the sole gate. Pre-filtering never discharges the node's obligation. _(xref:security.adoc[§13.2], xref:localization.adoc[§14.4].)_

== REST façade & addressing

* [[n28]]*N28.* The federation surface is the openEHR *ITS-REST* API relative to a *deployment-chosen base URL*. No path prefix is mandated or reserved by this specification - in particular `/rest/openehr` is a vendor deployment convention and is *not* part of it. A client MUST take the base URL from the registry / service discovery and MUST NOT hard-code a prefix. _(xref:addressing.adoc[§15].)_
* [[n29]]*N29.* A gateway MUST support the *canonical path form* `+{base}/v1/ehr/{ehr_id}+` for every ITS-REST resource it exposes, MUST accept the AQL predicate form `WHERE e/ehr_id/value = …`, and SHOULD accept `FROM EHR e[ehr_id/value=…]`. The forms are semantically equivalent; this spec's use of the `WHERE` predicate in examples is presentational. _(xref:aql-facade.adoc[§7.1].)_
* [[n30]]*N30.* A gateway MUST implement `+OPTIONS {base}/+`, describing the supported ITS-REST areas (federated / routed / unsupported), the accepted targeting mechanisms, the dedup mode, the timeout policy, and the *member endpoints behind the gateway* with at least `id`, `organisation` and `status`. The endpoint list MUST NOT require a patient identifier. _(xref:rest-facade.adoc#options-root[§7a.2].)_
* [[n31]]*N31.* On every request routed or dispatched to a single node - including `POST`/`PUT`/`DELETE` - the gateway MUST return the acting endpoint in the `openEHR-federation-endpoint` response header and SHOULD return the node's `system_id` in `openEHR-federation-system-id`. `Location` and `ETag` MUST be passed through unmodified. _(xref:rest-facade.adoc#write-headers[§7a.3], xref:result-set.adoc#response-headers[§9.5].)_
* [[n32]]*N32.* A gateway MUST NOT federate the openEHR *DEMOGRAPHIC* API; identity is resolved through the identity binding of <<n3,N3>>. Unsupported ITS-REST areas MUST be answered `501 Not Implemented` or routed to a single explicitly chosen node, and MUST be declared under <<n30,N30>>. `node_id`, `endpoint_id` and `system_id` MUST be *distinct namespaces* and the registry MUST resolve each unambiguously. _(xref:rest-facade.adoc[§7a.1], xref:identifiers.adoc#id-namespaces[§12a.1].)_

== Identifier hygiene at dispatch

* [[n33]]*N33.* In the parts of an outbound request that the gateway *composes* - the dispatched AQL, the request path, the query string and the headers - a node MUST be located by the `ehr_id` alone: the gateway MUST NOT dispatch any *directly identifying identifier* (xref:identity-resolution.adoc#directly-identifying-identifier[§5.1]) in *any* of those positions, including a `WHERE`/`SELECT`/`ORDER BY` path over `PARTY_IDENTIFIED.identifiers` / `DV_IDENTIFIER`, `PARTY_RELATED` or an `ENTRY`-level `subject`, and including the echoed query text. The gateway MUST consume such values in resolution and strip them, or *reject the query* (`400`). This does *not* extend to client-supplied *write payloads*: a commit body is archetyped clinical content, is passed through unmodified (<<n22,N22>>), and its contents are governed by the node's own validation, authorization and consent. _(xref:identity-resolution.adoc#identifier-hygiene[§5.4].)_
* [[n34]]*N34.* A node in a federation MUST be invocable on its local `ehr_id` alone, and the node's *environment* MUST provide a way to exchange a patient identifier for that `ehr_id` (the cross-reference role of <<n3,N3>>); it is immaterial to the federation whether the node, its organization's MPI, or a regional service fills that role. This specification does *not* mandate where a directly identifying identifier is stored and does *not* forbid a node from holding one - that is the node's own governance concern. _(xref:identity-resolution.adoc#node-obligation[§5.5].)_

== Targeting mechanisms

* [[n35]]*N35.* A gateway MUST support endpoint targeting *both* in AQL (`FROM ENDPOINT` / `ORGANISATION`) *and* outside it (the `openEHR-federation-endpoint` *request header* - never a query parameter); a client MUST support at least one. Both carry stable registry endpoint identifiers, never URLs. If both are present and the node sets *differ*, the gateway MUST reject with `400`; it MUST NOT merge or silently prefer one. Only the out-of-AQL form applies to non-AQL requests. _(xref:endpoint-directive.adoc#header-alternative[§8.4].)_

== Dedup and write safety

* [[n36]]*N36.* A write derived from a de-duplicated row MUST be routed on the target version's `creating_system_id`, not on the endpoint the surviving row was read from. A gateway MUST NOT route a versioned write to a node that merely *holds a copy*: if no reachable node has `system_id == creating_system_id`, it MUST reject with `409 Conflict` naming the controlling system rather than fork the object. Suppressed endpoints MUST remain visible in `meta`. _(xref:deduplication.adoc#update-routing-hazard[§10.3].)_

== Completeness, timeouts, ordering

* [[n37]]*N37.* The default fan-out strategy is *best-effort*: rows from the nodes that answered, every other node reported in `meta.endpoints[]`, HTTP `200`. `meta.complete` MUST be present and MUST be `true` only when every in-scope node reached status `active`. A stricter all-or-nothing mode MAY be offered but MUST be opt-in per request and declared under <<n30,N30>>. Best-effort applies to reads only. _(xref:partial-results.adoc#best-effort[§11.4].)_
* [[n38]]*N38.* A gateway MUST apply both a *per-node timeout* and an *overall query budget*, abandoning and marking `time-out` rather than failing the query; both values MUST be discoverable under <<n30,N30>> and the observed per-endpoint elapsed time MUST be reported (<<n40,N40>>). A client MAY shorten the budget via `Prefer: wait=`; a gateway MUST NOT extend beyond its own budget on request. A `time-out` endpoint means *unknown*, never *no data*. _(xref:partial-results.adoc#timeouts[§11.5].)_
* [[n39]]*N39.* For `ORDER BY` with `LIMIT n`, the gateway MUST dispatch `LIMIT n` per node and then re-apply `ORDER BY` and `LIMIT n` across the merged rows, with deterministic tie-breaking. For `OFFSET > 0` it MUST either reject (`400`), compute the page correctly from `k + n` rows per node, or serve it from a materialised ordered result - and MUST declare which; it MUST NOT push `OFFSET` down and present the result as a correct global page. An undirected aggregate MUST be rejected (`400`) with a reason, *never* answered with per-node aggregate rows; decomposable aggregates MAY be supported only where exactly correct and declared. `GROUP BY` groups spanning nodes MUST be merged or the query rejected. _(xref:partial-results.adoc#aggregation-and-ordering[§11.6], <<n14,N14>>.)_
* [[n40]]*N40.* `meta.endpoints[]` MUST carry, per endpoint, `id`, `status`, `error` (on error) and the gateway-observed `latency_ms`; it SHOULD carry `node_id`, `system_id`, `organisation`, `product`, `version` and `row_count`. A gateway MUST NOT invent product/version values it does not know. _(xref:result-set.adoc#endpoint-meta[§9.4].)_

== EHR-scoped routing, collisions, definitions

* [[n41]]*N41.* A gateway MUST resolve a path `ehr_id` to its owning node in priority order: explicit target on the request, then a held resolution binding, then an `ehr_id` → node index, then (reads only) an ask-all probe. For *writes*, ask-all MUST NOT be used: if the earlier steps do not yield exactly one node the gateway MUST reject with `400` and require an explicit target. _(xref:follow-up-routing.adoc#ehr-id-routing[§12.5.1].)_
* [[n42]]*N42.* _(Gateway, at request time.)_ If the same `ehr_id` is claimed by more than one node, the gateway MUST NOT choose between them: it MUST fail with `409 Conflict` listing the claimants and MUST report the collision as a federation integrity incident. _(xref:follow-up-routing.adoc#ehr-id-collision[§12.5.2].)_
* [[n42a]]*N42a.* _(Federation operator, at admission.)_ A federation MUST define *admission conditions* that a candidate node satisfies before it is accepted as a member, and those conditions MUST cover `ehr_id` generation (UUID-v4 or equivalent), non-reuse of `ehr_id` s, non-adoption of foreign `ehr_id` s on import, and federation-wide uniqueness of `system_id`. These are identifier-integrity conditions only, not a complete admission profile. _(xref:membership.adoc[§12b].)_
* [[n43]]*N43.* A gateway MUST route each `+{base}/v1/definition/…+` request to a *single explicitly chosen* node and MUST NOT present a union of nodes' templates as one catalogue. It MAY support *fan-out template upload*, which MUST be opt-in and explicit, reported per node, non-atomic (partial success reported, successes not rolled back, overall success never reported while a node failed) and declared under <<n30,N30>>. Template upload is the only permitted fan-out write; fan-out creation of clinical objects remains disallowed (<<n23,N23>>). _(xref:follow-up-routing.adoc#definition-routing[§12.6].)_
