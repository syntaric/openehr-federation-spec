= 17. Conformance points (consolidated)

A numbered, testable list feeding xref:testing.adoc[§16]. Each maps to requirements and a test track.

The *Actor* column names who is scored against the point. Most are the gateway, but not all: a `Node` point is an obligation of a member CDR and a gateway cannot discharge it, and an `Operator` point is verified at admission or in the registry rather than on any request (xref:testing.adoc[§16.2]). A gateway is not marked down for a point whose actor is not the gateway.

Conformance points are *appended, never renumbered* - a CP number is a stable citation, and `#cp-14` is expected to keep deep-linking. Where a point belongs topically next to an existing one, the suffix form (CP-33a) is used instead.

Every normative requirement should be named by at least one conformance point, or by a test track. The closure is computed by `tools/traceability.sh`, which runs in CI: a requirement scored by neither must appear in `tools/traceability-exceptions.txt` with a reason, so "deliberately unscored" is a recorded decision rather than an oversight.
